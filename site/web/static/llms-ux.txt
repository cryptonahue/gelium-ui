# Gelium UI — UX decision pack (for agents)

Machine-oriented rules. Human narrative + sources: /docs/screens , /docs/feedback .
Obey Forms (/docs/forms), Content style, Server contracts, Responsive. Stack: server HTML + gelium-ui CSS; JS optional.

## MUST do before generating UI

1. SCREEN TYPE: hub | list | detail | form | confirm | settings | queue | result
2. USER JOB: one sentence
3. ONE PRIMARY ACTION
4. STATES: loading | empty | error | success
5. CONTROLS: map via choose-the-right-control + forms contract
6. SERVER: GET read; POST+303 mutate; 422+X-Gelium-Validation for field errors
7. THEME: class theme-* on html
8. NARROW: stack; min-width:0; no overflow-x:hidden on body
9. FEEDBACK: pick a FEED-* id from the matrix below (do not improvise)

## SCREEN types → building blocks

| Type | Blocks |
|---|---|
| hub | title, short context, one primary button |
| list | data-table OR list/card, filters, pagination, empty-state |
| detail | title, status badge, body, secondary actions |
| form | fields, validation-summary, primary+cancel |
| confirm | dialog/confirm route, destructive button, cancel link |
| settings | list rows, switch/select |
| queue | list/table, badge, row POST actions |
| result | success banner/alert, next links, optional toast |

## FEEDBACK matrix (do not improvise)

| ID | Situation | Use | Never |
|---|---|---|---|
| FEED-VAL | Field validation after submit | validation-summary + inline field errors + 422 | toast-only; banner for validation |
| FEED-INLINE | Rare live field help after interaction | inline after interaction | premature on empty focus; modal |
| FEED-OK-TOAST | Task OK, stay in flow | short success toast (optional one action) | error styles; OK-only modal |
| FEED-OK-PAGE | Task OK and page IS the result | success banner/inline-alert on result; toast optional echo | toast-only with no page context |
| FEED-FAIL | Hard task/network fail (not a field) | inline-alert/banner + retry | vanishing toast if critical |
| FEED-SYS | System-wide notice | layout banner | mix with field errors |
| FEED-PAGE | Page-level status/warning | banner/alert in main column | global chrome for one-page msg |
| FEED-EMPTY | Empty collection | empty-state + CTA | blank table |
| FEED-LOAD-FAIL | Section fetch failed | error-state + retry | infinite skeleton |
| FEED-LOAD-LIST | List/table loading | skeleton inside list region | full-app blocker every refetch |
| FEED-LOAD-PAGE | Whole view first paint | one page skeleton then content | nested forever blockers |
| FEED-ROW | One row/item action failed | error in/near row (+ summary if many) | toast-only with no row marker |
| FEED-PARTIAL | Batch some OK some not | outcome summary + per-item status | single green toast "Done" |
| FEED-CONFIRM | Irreversible/consequential | confirm dialog/page + POST | toast-only delete |
| FEED-FYI | Low-priority FYI | toast/snackbar-class | toast for validation lists |

### Toast rules (FEED-OK-TOAST / FEED-FYI)

- Brief, low priority (M3 snackbar). OK if missed when non-critical.
- At most one short action (e.g. Undo only if truly reversible).
- After 303: toast may echo; durable success still on result page when needed (FEED-OK-PAGE).
- Never sole channel for FEED-VAL or FEED-PARTIAL failures.

### Loading rules

- FEED-LOAD-LIST: skeleton scoped to list/table.
- FEED-LOAD-PAGE: one shell skeleton.
- FEED-LOAD-FAIL: replace skeleton with error-state + retry.

Sources: GOV.UK error summary + notification banner when-not; USWDS alert vs site-alert; M3 snackbar vs dialog; NNG error timing/severity.

## NAV quick rules

| Need | Prefer |
|---|---|
| Section hierarchy 1–3 levels | side nav / drawer |
| 3–5 app peers (small viewport) | navigation bar |
| Same object, alternate views | tabs / segmented-button |
| Long docs sections | on-this-page |

USWDS: skip heavy side nav on tiny sites. M3: nav bar for few top-level views.

## HIERARCHY

Order: H1 title → context → primary action → main content → secondary.
F-pattern (NNG): important info top/left; do not bury sole CTA under the fold of a long table.

## COPY

Errors = fix first ("Enter the name"). Toasts = verb+result. Empty = what/why/next.
Partial = counts + next ("3 sent, 2 failed"). See content-style.
